# План реализации

Объём и контракты — в [отчёте](report.md): шесть сервисов, customer/admin, до 10 вещей, резерв при оформлении, тестовая оплата. Основной запуск локальный, распределённый CDN не реализуется.

## Этапы

1. Создать Auth/Catalog/Cart/Order/Notification/Image на ASP.NET Core, миграции, Dockerfile; шесть PostgreSQL, RabbitMQ, Redis, SeaweedFS и демонстрационный LGTM.
2. Auth: регистрация customer, bootstrap admin из Secret, PasswordHasher, RS256 JWT, проверки ролей/владельца в API, защита внутренних маршрутов сервисными ключами.
3. Catalog: seed 20–30 вещей, публичная главная/каталог/пресеты, admin create/update, проверка image_id через Image; атомарные reserve/complete/release. Redis только общей первой страницы, TTL 60 с, DEL после правок и fallback.
4. Cart: максимум 10, без дубликатов/резерва; CartItemAdded и CartItem одной транзакцией. Order: снимки/идемпотентность, сага, OrderReserved и итоговое событие, восстановление.
5. Outbox Catalog/Cart/Order: триггер NOTIFY, LISTEN до drain на старте/переподключении, supervised publisher и confirms. Cart: отдельная очередь изменений наличия, version/dedup, персональные outbox-события владельцам корзин. Notification: basicConsume push, транзакционная история и последовательность пользователя, ACK после commit, дедупликация и dead-letter.
6. SignalR только WebSockets с skipNegotiation; запрет SSE/Long Polling на обеих сторонах. Resume/ACK курсора, клиентская дедупликация, восстановление после разрыва; Nginx Upgrade, JWT-expiry и исключение access_token из логов. Никаких таймерных запросов статуса/уведомлений.
7. Интерфейс: главная с пресетами, вход/регистрация, каталог/карточка, корзина/оформление, заказ/уведомления и маленькая admin-форма. Catalog хранит страницы и пресеты с page_id; Image хранит metadata в image_db, файлы в S3 и выдаёт по ID; Nginx кеширует /media, без облачного CDN.
8. OTLP во всех шести API, traceparent в HTTP/AMQP, логи в Loki, Grafana-дашборды, трейсы Tempo и метрики Mimir. Проверить поиск одного заказа через все его этапы, без секретов/персональных данных в телеметрии.
9. Compose и Minikube: 8 Deployment, 9 StatefulSet/PVC; Secrets, Services, probes, лимиты ресурсов. Проверить оба запуска и записать фактические команды.

## Приёмка

- Customer не создаёт admin, не пишет каталог и не читает чужие покупки; неверный/истёкший JWT → 401, отсутствие роли → 403. Выход закрывает WS.
- Catalog хранит пресеты в БД; page_id/preset_id выбирают нужную страницу/фильтры.
- Catalog reserve/sale/release атомарно создают versioned events; Cart видит недоступность и отправляет персональный push, дубли/старые версии игнорируются. Вход в корзину показывает live-наличие.
- Корзина не резервирует; 11-я вещь отклоняется; повтор добавления не создаёт вторую позицию/событие. CartItemAdded доходит до своего пользователя.
- Успех → CONFIRMED/SOLD; отказ → CANCELLED/release; конкуренция и частично недоступный набор не дают двойной продажи/частичного резерва.
- Повторы ключа, команды, события и WS-доставки безопасны; запоздавший reserve не обходит RELEASED. Crash после SOLD восстанавливается.
- В Network нет регулярных GET статуса/уведомлений, нет SSE/Long Polling; новые события будят outbox без таймера. Reconnect LISTEN/broker/WS восстанавливает данные без потерь истории.
- Notification DB показывает получателя, payload, created_at и попытки/sent_at; sent_at не называется прочтением.
- Кешируется только первая общая страница; admin-правки инвалидируют кеш, остатки/цена покупки — БД; Redis down → fallback.
- Фото сохраняются в S3, admin-права/формат/размер проверяются; повторная картинка получает новый URL. Браузер получает URL в JSON и байты по пути Nginx→Image→S3.
- Логи, метрики и трейсы видны в Grafana; trace связывает HTTP/AMQP; токены/пароли отсутствуют. Падение observability не блокирует покупки.
- Pod БД/broker/S3 пересоздаются с сохранением PVC; проверены три сценария и целевые задержки отчёта.

Это критерии будущей реализации, а не отчёт об уже выполненных тестах приложения.

**Перед сдачей:** согласовать шесть микросервисов вместо 3–5 по исходному ТЗ. Рабочие манифесты и приложение пока не реализованы.
